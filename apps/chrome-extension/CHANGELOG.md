# Chrome 扩展更新日志

扩展单独发版，标签为 `ext-vX.Y.Z`，版本号取自 `apps/chrome-extension/package.json`。推送标签后，扩展工作流把对应段落写进 GitHub Release 的说明，所以**打标签前先在这里写好该版本的条目**。

## [0.2.0] - 2026-11-26

需要 Nexus Portal 服务端 0.4.0 才能收藏网页；新标签页仍然支持 0.3.0。

### 新增

- **不连接也能用（此扩展的本地收藏，UI 焕新 U1）**：新安装直接可用的新标签页——首页、收藏、应用目录、外观与搜索设置都在扩展内（IndexedDB `nexus-local`），不跳转网站、不需要服务器；工具栏按钮「保存到此扩展」与右键菜单保存到同一份收藏，同时保存不会丢（每次保存是一个 IndexedDB 事务）；本地保存可以撤销，已收藏的网址会说明并更新原来那条。不使用 `chrome.storage.sync`。
- 设置页新增「此扩展的本地收藏」：数量、打开收藏、导出备份；连接账号后可选择新标签页与收藏按钮使用本地收藏还是账号里的收藏，切换不删除另一边。
- 以前未连接时存下的草稿，可在收藏弹窗里预览后「放入本地收藏」，不会静默归入任何账号。
- **收藏到 Nexus**：工具栏按钮预填当前页的标题和网址，可选择分组、标签，可勾选「同时固定到首页」（默认不勾）；已经收藏过的网址会先说明它在哪里，不会重复保存。
- 右键菜单「添加当前页面到我的收藏」与「添加此链接到我的收藏」（取链接本身的地址，不会误存所在页面）。浏览器内部页面、本地文件等不支持的地址会说明原因。
- 保存先写进本机再发送：断网、关闭弹窗或浏览器重启后，联网时自动补发；补发使用同一个 opId，服务端不会多存一条。工具栏徽标显示还没同步的数量。
- 没有连接或只有只读授权时，保存为草稿；授权后由你确认保存到哪个账号再提交。
- 设置页「授权收藏」：0.1.x 的只读授权不会被自动扩大，需要在门户里批准新的权限后替换（旧授权随即撤销）。
- Microsoft Edge 单独打包：`nexus-portal-edge-vX.Y.Z.zip`（不含 manifest key，供 Edge 加载项商店使用）。
- Firefox 版本（桌面版 140+）：`npm run package:firefox` 生成 `nexus-portal-firefox-vX.Y.Z.zip`，打包前通过 Mozilla `addons-linter` 检查（0 个错误）。尚未在真实 Firefox 中安装验证，也尚未提交 addons.mozilla.org 签名。

### UI 焕新与 UI v2

- 新标签页直接复用门户的首页组件，随门户 0.4.0 一起更新，例如首页 4 × 2 与「快速打开」、桌面首排按宽度自动占满一行。完整列表见门户的 `CHANGELOG.md`。
- 弹窗、右键菜单和选项页都写明真实去处：「保存到：我的收藏（账号「…」）」或「保存到：此扩展的本地收藏」，不再用「Nexus」「收藏库」这类含糊的说法。
- 分组显示完整层级，未分组的统一叫「未分组」。
- 弹窗与选项页的链接改到门户的 `/settings/favorites`。
- 本地新标签页里的旧链接 `#/library`、`#/catalog` 会转到「我的收藏」。
- 首屏按记住的主题绘制，浅色主题不再先闪一下深色；弹窗与选项页也跟随主题。
- 扩展令牌的权限范围不变。

### 变更

- 权限：`storage`、`activeTab`、`contextMenus`，以及连接时授予的那一个服务器地址；不需要历史记录、书签或全部网站的权限。
- 授权被撤销时，还没发送的收藏保留为草稿，其余数据清除。

### 修复（公开版复审）

- **同时保存不再丢收藏**（NEX-05）：此前弹窗与右键各自读改写同一个存储键，两次几乎同时的保存都显示成功，最后只剩一条。现在收藏队列存在 IndexedDB（每条收藏一条记录，按 opId），每次变更都是一个事务；弹窗与右键都通过后台的同一个保存命令写入，发送状态的更新、确认草稿、丢弃、退出账号都不会互相覆盖。只有已经写入本机的收藏才会显示「已保存」——后台在回答前被浏览器停止时，弹窗以本机记录为准，用同一个 opId 再提交也不会多存一条。后台正在发送收尾时又存下的收藏会紧接着再发送一次，不会等到下次打开弹窗或新标签页。0.2.0 保存在旧位置的收藏会在第一次启动时搬过来。
- **授权被撤销时立即提示**（ADR-019）：后台发送收藏时如果服务端回答 401（门户或 LiteSync 中退出了全部设备、账号被停用、设备被撤销），扩展立刻标记授权失效：工具栏徽标显示「!」、按钮提示「授权已被撤销，请重新连接」，右键保存会打开设置页说明原因，弹窗直接给出提示；还没发送的收藏全部保留为草稿，不会被删除，也不会改用别的账号提交——草稿记住它属于哪个账号，只有重新连接同一个账号才能确认发送。账号中心暂时不可用（503 `IDENTITY_UNAVAILABLE`）、服务器繁忙或断网时，收藏原样保留，之后再发。
- 首页已固定满 36 个时，勾了「同时固定到首页」的收藏照常保存，弹窗说明没有固定（NEX-07）。

## [0.1.4] - 2026-11-02

服务端要求不变：0.3.0 或更高版本，每日一图需要 0.3.2。

### 修复

- 快捷方式扩展区收起时，焦点不再丢失：先移到展开按钮，再让扩展区失去交互。Chrome 控制台不再提示 `Blocked aria-hidden`。

## [0.1.3] - 2026-11-02

每日一图需要 Nexus Portal 服务端 0.3.2 或更高版本；其他功能仍然支持 0.3.0。

### 修复

- 每日一图直接从服务端读取，不再依赖门户先把图片存进壁纸库。图片与其他壁纸一样缓存在扩展里，断网时继续显示上一张，并在网络恢复后自动更新。

### 变更

- 每日一图模式下不再显示「换一张」，这个模式每天只有一张图。

## [0.1.2] - 2026-11-01

仍然需要 Nexus Portal 服务端 0.3.0 或更高版本。

### 修复

- 更新扩展时不再丢失连接。扩展现在有固定的 ID，把新的 ZIP 拖到 `chrome://extensions` 或覆盖原来的文件夹后，Chrome 会原地更新同一个扩展：连接、缓存、界面偏好和网站访问权限都会保留，也不再打开欢迎页。之前每次拖入 ZIP，Chrome 都会按随机的解压目录算出新的 ID，把它当成另一个扩展安装。

### 升级说明

- 从 0.1.0、0.1.1 升级时需要最后重新连接一次：新旧版本的 ID 不同，新版本读不到旧版本的数据。连接成功后，移除旧的 Nexus 卡片，并在门户「设置 › 数据、同步与安全 › 浏览器扩展」中撤销旧设备。

## [0.1.1] - 2026-10-30

仍然需要 Nexus Portal 服务端 0.3.0 或更高版本。

### 变更

- 新标签页的快捷方式扩展区与门户首页保持一致：鼠标移到首排时临时展开，移出后自动收起；点击面板下方的箭头按钮固定展开，再次点击收起。按钮移到面板底部居中，可点击范围更大，平时弱化显示。

### 更新方法

- 把新的 ZIP 解压到原来的文件夹，再到 `chrome://extensions` 点扩展卡片上的刷新按钮。连接和缓存都会保留。

## [0.1.0] - 2026-10-29

第一个版本：Chrome 开发者模式手动安装，需要 Nexus Portal 服务端 0.3.0 或更高版本。

### 新增

- 用扩展内置的页面替换 Chrome 新标签页，复用门户首页的组件：壁纸、时钟、搜索、快捷方式、分组与全部应用、服务状态、首页显示设置。
- 本地缓存优先：打开新标签页时直接显示上次同步的导航，不等网络；随后在后台检查更新。
  - 有变化时更新缓存和已打开的页面；没有变化时服务端只回一个很小的 304。
  - 30 秒内不重复检查；多个新标签页同时打开时只有一个去同步。
  - 断网或服务端故障时继续显示缓存，不会清空页面。
- 图标和壁纸缓存在 IndexedDB 中：最多 400 个图标、6 张壁纸、80 MB，最久未用的先清理。
- 连接与授权：
  - 只读设备令牌，经门户中登录的用户核对连接码并确认后才发放。
  - 扩展只申请 `storage` 权限，以及用户填写的那一个门户地址的访问权限。
- 扩展设置页：连接状态、最近同步时间、立即同步、清理缓存、更换服务器、断开连接（同时撤销令牌）。
- 授权被撤销、访问密码更改或缓存损坏时：清除本地导航数据，提示重新连接或重新下载。
