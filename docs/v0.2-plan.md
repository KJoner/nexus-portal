# Nexus v0.2.0 审计与实施计划

更新：2026-10-29 · 基线：main `3841dae`（v0.1.0 之后）

v0.2.0 是一次体验升级，不是重写。下面先说明现有实现，再列出每个批次的改动范围。凡是现有能力能用的地方都直接复用，不另起一套。

## 一、现有实现（只读审计）

| 需求 | 现在的实现 | 缺口 |
|---|---|---|
| P0-A 快捷方式 | `pins` 是单一顺序，`MAX_PINS = 12`。桌面 Dock 显示前 `dockSize`（3–7）个，加上服务和「全部应用」；手机显示 `行数 × 4 − 服务数` 个（`layout.ts`） | 桌面超出首排的部分看不到（设置页标为「仅手机」）；没有扩展区和分页 |
| P0-B 排序 | `apps` 数组顺序就是抽屉和设置中各分类内的顺序；`categories` 数组顺序就是分组顺序；`pins` 单独维护首页顺序。「管理分类」对话框只能上下移 | 应用没有排序界面，也没有移动应用的操作；跨分类移动只能进编辑器改分类 |
| P0-C 壁纸 | 内置 1 张照片（`fallingwater.jpg`，128 KB，只有一种尺寸）和 3 种渐变；上传的图片由 sharp 生成 AVIF/WebP/JPEG 各三档，外加模糊占位图；Service Worker 用 CacheFirst 缓存；暖调/原色、遮罩、亮度、模糊、桌面和手机焦点都已实现 | 没有公共图源和每日图片；「每日轮换」标为「尚未实现」；没有收藏、不喜欢、上一张；署名只是一段文字 |
| P0-D 显隐 | 顶栏固定显示，只有访客模式会隐藏服务状态；日期和图标名称可以开关；`/settings` 路由始终可以访问 | 没有自动隐藏、极简模式和预设 |
| P0-E 搜索 | `matchApps` 的排序是：名称前缀 > 词首或别名前缀 > 包含；结果按「网址 → 应用 → 网页 → 建议」分组 | 没有拼音、缩写、不连续字符匹配和容错；没有高亮；回车直接打开第一行；编辑器里不能编辑别名（模型已支持 `aliases`） |
| P1 | 图标都是 `<a>`，中键和 Ctrl+点击天然可用；同一主机的地址会给出警告 | 右键菜单没有「在新标签页打开」和「移到最前/最后」；首页 HTML 没有 `Cache-Control` |

## 二、可以直接复用的部分

- **配置操作体系**：共享的 `applyOp` / `invertOp`、离线队列、SSE 同步、带撤销的提示条。新的排序也走这一套，多设备同步和撤销自然就有了。
- **dnd-kit**：已有 Pointer 和 Keyboard 两种传感器的用法；排序模式在此基础上加了 Touch（长按）传感器和跨容器拖动。
- **图片管线**：`WallpaperStore` 的 sharp 管线（重新编码、去掉 EXIF、生成多档尺寸、占位图）。远程导入、图库和每日图片都复用它。
- **外部请求**：`IconProxy` 的「域名白名单 + 手动跟随重定向 + 大小和类型校验 + 磁盘缓存」模式，以及 `net/http.ts` 的 SSRF 防护（`guardedLookup`）。
- **交互组件**：`ContextMenu`、`ActionSheet`、设置页的 `Row` / `Segmented` / `Switch`、外观页的「预览后应用」草稿机制。

## 三、数据模型与 API 变更

配置仍然是一份经过校验的 JSON 文档，不引入新的数据库。

- **批次 1**
  - `MAX_PINS` 从 12 提高到 36。
  - 新增 `settings.home.shortcuts`：模式（单排 / 可展开 / 固定展开）、每页行数、分页指示、记住展开状态。字段都有默认值，v0.1 的文档可以原样读取。
  - 新增操作 `app.move`（分类内或跨分类移动）和 `category.move`。
  - `apps` 按分类顺序分块存储：规范化时做稳定排序，任何可见顺序都不变。这样一来，移动和撤销都能精确还原到原来的数组位置。
  - **结论：不需要独立的排序字段**，现有数组就足以表达顺序。
- **数据库迁移 v4**
  - 写入 `config_format = 2`，并在迁移前自动备份到 `/data/backups/nexus-v3-<时间>.db`（`VACUUM INTO`，只保留最近 5 份）。
  - 旧版本看到更高的数据库版本会拒绝启动，不会读到超过 12 个固定项后悄悄退回默认配置。
- **批次 2**
  - `settings.look` 增加背景来源和切换规则；新增 `settings.ui`，存放显隐方式、预设和桌面/手机各自的布局参数。
  - `wallpapers` 表增加来源、署名/许可、亮度等列（迁移 v5）。
  - 新增接口：远程图片导入、图库和每日图片（服务器下载后缓存，同源提供）、Unsplash 元数据代理（可选）。
- **批次 3**
  - 搜索索引放在 `shared/search.ts`，按匹配强度分级。
  - 拼音用 `pinyin-pro`，懒加载，不影响首屏。
  - 编辑器加入别名编辑。

## 四、兼容与安全风险

| 风险 | 处理 |
|---|---|
| 回滚到 v0.1 后，超过 12 个固定项会让旧版退回默认配置，并在下次写入时覆盖 | 迁移 v4 让旧版拒绝启动；升级前自动备份；回滚方法是恢复备份（见发布说明） |
| Service Worker 更新前，旧版前端读到新配置 | zod 默认丢弃未知字段；旧版前端的 `pin.add` 最多到 12 个，不会写坏数据 |
| 远程图片引发 SSRF | 只允许公网地址，DNS 解析后再校验；不自动跟随重定向（或限定白名单）；限制大小、类型、超时；一律经 sharp 重新编码 |
| 第三方 API Key | 只放在服务器的环境变量里，浏览器只拿到图片地址和署名信息 |
| Unsplash 隐私 | 条款要求图片必须直链，浏览器会直接访问 `images.unsplash.com`，因此默认关闭，配置 Key 后才会出现 |
| 搜索泄露 | 应用匹配全部在本地完成；索引网址路径时去掉查询参数和疑似令牌的片段；结果里只显示主机名 |
| 隐藏全部控件后无法进入设置 | `/settings` 始终可访问，另有键盘快捷键、桌面右键菜单、手机长按空白处、搜索里的「打开设置」 |

## 五、图片来源结论（2026-10-29 调研）

- **Bing 每日图片：不集成**
  - 没有官方 API，`HPImageArchive` 是未公开的端点。
  - 微软服务协议规定 Bing 上的图片仅限个人非商业使用，未经授权不得下载、复制、再分发，也不得用来构建自己的产品。
  - 端点自己的字段也写着「仅限用作壁纸」，而且有些图片不开放。
  - 图片版权多属 Getty 等第三方。
- **Wikimedia Commons 每日图片：作为「每日一图」**
  - 用 Commons Action API 获取当天的文件和 `extmetadata`（作者、许可、链接）。
  - 服务器缓存缩放后的副本，同源加载，CSP 不用改。
  - 必须带描述性的 User-Agent。
  - 署名遵循 CC BY-SA 等许可。
  - 竖幅或近方形的图片约占三分之一，遇到时回退到最近一张横幅图。
- **内置精选图库**
  - 从 Commons 精选 CC0、公有领域或 CC BY(-SA) 的横幅照片，按「自然、建筑、极简、城市夜景、深色氛围」分类，清单写在代码里。
  - 第一次使用时由服务器下载、缓存并记录许可；大图不放进仓库和镜像。
  - 离线时回退到内置的流水别墅和渐变色。
- **Unsplash：可选**
  - 部署者需要自己申请 Access Key（`NEXUS_UNSPLASH_ACCESS_KEY`），所有部署共用同一个 Key 是不允许的。
  - 图片必须直链；每次设为壁纸时由服务器触发一次 `download_location`。
  - 署名写成「Photo by 作者 on Unsplash」，带上 UTM 参数。
- **不集成**
  - Pexels：许可禁止用于壁纸应用。
  - Pixabay：图片最大只有 1280px，而且禁止长期直链。
  - NASA APOD：逐张版权不同，接口也即将停用。
  - Picsum：是不稳定的随机地址。

## 六、Bonjourr 借鉴与取舍

Bonjourr 采用 GPL-3.0 许可，这里只参考交互思路，不复制代码。

- **借鉴**
  - 切换频率：每次打开 / 每小时 / 每天 / 锁定。
  - 预加载下一张，切换时淡入。
  - 右下角署名条。
  - 单个组件可以隐藏，也有「只显示时钟」这类细分选项。
  - 右键直接跳到对应设置。
  - 链接样式和每行个数可调。
  - 精简与完整两档设置。
- **不照搬**
  - 依赖中心化代理和共享 Key。
  - 它的 URL 代理能转发任意地址，存在 SSRF 风险。
  - 用 WebGL 信息判断低性能设备，属于指纹识别。
  - 21 种纹理和视频背景。

## 七、批次与文件范围

1. **批次 1：快捷方式、排序、持久化**（`feat/v0.2-shortcuts`）
   - `shared`：`schema` / `ops` / `layout` / `defaults` 及测试。
   - `server`：`db` 迁移与自动备份。
   - `web`：`Dock`、`DesktopHome`、`SearchSlab`、`MobileHome`、`HomeLayoutPage`、`AppsPage`、新增 `SortMode`、`actions`、`lib/dnd`。
   - 端到端测试。
2. **批次 2：动态壁纸、图片来源、显隐与极简模式**
   - `server/wallpapers/*`（导入、图库、每日图片、Unsplash）、迁移 v5、CSP。
   - `Wallpaper`、`AppearancePage`、`TopBar`、首页的显隐、新增「显示与布局」设置。
3. **批次 3：搜索增强与应用管理**
   - `shared/search` 匹配分级与高亮、拼音懒加载、`SearchSlab` / `MobileSearch` / `Drawer`、`AppEditor` 的别名编辑和重复检测。
4. **批次 4：综合验收、性能与发布**
   - 桌面 Chrome/Edge 与移动 WebKit 的端到端测试、窄视口和低高度、两台设备同步与断网恢复。
   - 从 v0.1.0 真实升级、回滚到恢复备份的演练。
   - CHANGELOG、迁移说明、回滚说明。

每个批次在独立分支上完成，类型检查、单元测试、组件测试和端到端测试全部通过后再合并到 main。推送到 GitHub 和打版本标签之前都会先问你。
